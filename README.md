# VisualStream

大模型推理记录的重放工作台，同时提供 **浏览器版与 Tauri 2 桌面版**，共用 Vue 3 + TypeScript 前端。当前实现 **Megakernel + Perfetto Protobuf**，默认空白启动，由用户导入记录；计算模式和文件解析器分别注册。

## 浏览器版启动

需要 Node.js 22.12+；本项目在 Windows、Node.js 26 和 Edge 上验证。

Windows 下双击根目录的 `run.cmd` 即可启动：缺少依赖时自动安装，准备或校验 Perfetto 引擎资源，然后启动服务并自动打开浏览器。首次准备需要联网；启动后保持窗口开启，按 Ctrl+C 停止服务。出错时窗口会保留，便于查看原因。

也可以手动执行：

```sh
npm install
npm run setup:assets
npm run dev
```

打开 `http://127.0.0.1:5173`。默认显示空白会话，可以选择或拖入自己的 trace，也可以从左侧历史文件重新载入之前导入的记录。

`setup:assets` 首次需要联网下载官方 Perfetto Worker、32 位与 Memory64 WASM 及许可证，默认锁定 `v59.1-79997ada9`，生成文件哈希清单。之后校验本地缓存，不需要再次下载。`public/vendor/perfetto` 为生成目录，不提交源码。要主动更新引擎，运行 `npm run setup:assets -- --refresh`，更新后重新执行测试。

运行时不上传 trace，也不请求第三方 CDN。部署时一起提供 `dist` 中的 Worker 和 WASM 资源；使用 HTTP 或 HTTPS，不能直接双击 `index.html`。

## 桌面版启动与打包

Windows 开发环境需要 Node.js 22.12+、Rust 1.90+（MSVC 工具链）、Visual Studio 的 C++ 桌面开发工具与 Windows SDK，以及 Microsoft Edge WebView2 Runtime。使用现有 Rust 工具链即可，不要求切换全局默认版本。其他系统需另外安装 Tauri 对应的系统依赖；本轮交付和验收目标是 Windows x64。

Debug 开发模式：双击根目录的 `run-desktop-debug.cmd`（原 `run-desktop.cmd`），或执行：

```sh
npm install
npm run desktop
```

启动时自动准备 Perfetto 引擎资源并启动前端开发服务，随后打开桌面窗口。首次 Rust 编译会下载依赖，耗时明显长于后续启动。桌面开发服务使用 5174 端口，浏览器入口仍使用 5173，可以同时启动 `run.cmd` 和 `run-desktop-debug.cmd`；桌面开发服务的地址也能在浏览器访问。

Release 正式模式：双击 `run-desktop-release.cmd`，会构建最新代码并打开独立客户端，不生成安装包，也不启动开发服务。已有构建时可执行 `run-desktop-release.cmd --no-build` 直接启动。详细说明见 [run-desktop-release.md](run-desktop-release.md)。

构建 Windows 安装包：

```sh
npm run desktop:build
```

输出的独立程序在 `src-tauri/target/release/visualstream.exe`，安装程序在 `src-tauri/target/release/bundle/nsis/`。发行程序内嵌前端、解析 Worker 和 WASM，不需要启动 Vite 或本地 HTTP 服务，也不需要安装 Node.js / Rust。安装程序在缺少 WebView2 时按 Tauri 默认方式引导安装，首次补装运行时需要联网；已有运行时后，重放功能离线运行。当前为未签名的本地构建，尚未接入自动更新。

桌面版的「导入 trace」「打开项目」「保存项目」使用系统文件对话框；支持多选 trace 与中文路径，取消操作不修改会话。拖入文件继续复用网页导入流程。桌面权限仅授予主窗口的窗口控制、文件对话框、读取、文件信息与项目写入，实际路径由文件对话框授权，不配置任意目录访问权限。两端项目格式相同，可互相打开；自定义 trace 仍按指纹关联，需要重新选择源文件。

桌面窗口隐藏系统标题栏，在工作台右上角提供最小化、最大化 / 还原、关闭按钮。拖动顶部品牌或空白区域可以移动窗口，双击可最大化 / 还原；主题切换、项目操作和窗口按钮保持独立点击。浏览器版不显示窗口按钮。

`npm run build` 仍只输出浏览器网站，`npm run desktop:build` 输出桌面安装包，两个入口互不替代。桌面版当前继续使用同一套 Perfetto WASM 解析与 256 MB 单文件限制；原生 Trace Processor 和大文件后端后续独立接入。

## GitHub Actions 自动构建

[构建工作流](.github/workflows/build.yml) 在发布 `v` 开头标签对应的 **Release（正式版本）或 Pre-release（预发布版本）** 时执行打包。工作流监听 `release.published` 并检查标签前缀，支持从草稿发布这两种版本。单独推送标签、保存草稿或编辑已发布版本不会执行打包。

首次启用或修改触发条件后，先将工作流提交并推送，再创建指向该提交的新标签。标签所指向的提交必须包含更新后的 `.github/workflows/build.yml`。例如：

```sh
git add .github/workflows/build.yml README.md
git commit -m "Build published releases with GitHub Actions"
git push origin master
git tag v0.1.2
git push origin v0.1.2
```

示例标签 `v0.1.2` 应替换为尚未使用的版本号。随后在仓库的 **Releases → Draft a new release** 中选择该标签，按需勾选 **Set as a pre-release**，发布正式版本或预发布版本均可触发构建。标签也可以在创建 Release 时从最新提交创建。已有标签仍指向原来的提交，不会随分支更新而自动移动。

工作流使用 Windows x64 环境、Node.js 24 与 Rust stable，按锁文件安装依赖并运行单元测试，然后通过现有 Tauri 构建入口准备 Perfetto 资源、执行类型检查、打包网页与 Release 客户端。npm、Rust 和 Perfetto 资源均有缓存。

构建完成后，工作流会自动将独立客户端 `visualstream.exe`、NSIS 安装程序和网页压缩包 `visualstream-web.zip` 上传到对应 Release 的 **Assets**，正式版本与预发布版本均支持。

对应运行页面的 **Artifacts** 同时保留以下产物，保留 14 天：

| 产物名称 | 内容 |
| --- | --- |
| `visualstream-windows-x64` | 独立运行的 `visualstream.exe` |
| `visualstream-windows-x64-installer` | Windows NSIS 安装程序 |
| `visualstream-web` | `dist` 网页静态资源，包含 Perfetto Worker 与 WASM，可部署到 HTTP / HTTPS 静态站点 |

无需额外配置仓库密钥。上传使用 GitHub 自动提供的令牌，构建任务授予 `contents: write` 权限；重复执行时会替换该 Release 中的同名附件。日常下载使用 **Releases → 对应版本 → Assets**，也可在 **Actions → Build → 对应运行 → Artifacts** 下载构建产物。

## 已实现

- 独立配置计算模式与文件解析器；当前只有 Megakernel 模式和 Perfetto 解析器，支持自动识别。
- 多文件会话、SHA-256 去重、导入进度、取消和文件错误提示。
- 多卡 → CU → Group 资源树；`block_N` 解释为 CU N，不同 CU 的 `group_0` 各自独立。
- Canvas CU 矩阵、当前任务表、事件详情、原始任务名称与额外属性查询。
- 时间轴概览、轨道纵向滚动、光标缩放、平移、播放头定位、轨道展开与事件选择。
- 算子按忽略数字编号后的名称统一着色，时间轴、CU 矩阵、任务表、搜索与详情共用颜色规则；显示与搜索保留原始名称。
- CU 利用率：支持整个时间周期和划选范围，显示总体、每卡与逐 CU 指标；支持计算卡筛选、排序和 CU 联动。按每个 CU 的任务活动时间并集计算，重叠任务不重复计入。
- 播放 / 暂停、可调慢放、精确跳转、前后事件边界、选区循环、播放头跟随。
- 时间区间统计：边界裁剪后的事件数、累计耗时、单来源活动并集。累计耗时包含并发。
- 搜索、时间书签、项目 JSON 保存与恢复；保存内容还缓存到 IndexedDB。
- 多来源时钟偏移配置。来源默认相对起点对齐；卡号与 rank 是文件名提示，界面明确标记同步尚未验证。

默认启动为空白会话，不内置或自动加载 trace。左侧「当前会话」「历史文件」「重放信息」和「时间书签」可分别折叠；成功导入的原始文件与解析配置保存在本机 IndexedDB，点击历史文件即可重新加入当前会话，无需再次选择原文件。移出当前会话后历史记录仍保留，也可单独删除历史记录。浏览器与桌面客户端各自保留本地历史。

资源管理器各分区使用独立标题栏和边框，当前会话优先占用文件区高度，历史文件限制高度并独立滚动。重放信息与时间书签固定在底部，折叠后释放的空间交给上方文件区；内容较多时各列表独立滚动，分区标题始终保留。

当前会话仅通过复选框多选，点击文件卡片会将时间轴纵向定位到该文件的轨道，不改变勾选状态和播放时间；未勾选的文件需先勾选再定位。导入的文件默认勾选；勾选几个便展示几个，清空选择时主视图和时间轴为空，播放不可用。概览、搜索、任务和利用率随选择更新。顶部计算卡筛选进一步筛选已勾选的文件。项目 JSON 保存文件指纹与显示选择；打开项目时优先从本机历史中找回原文件，缺少的文件再手动导入，旧项目默认显示全部来源。项目本身不嵌入原始 trace。

## 操作

标题栏高 40px，右侧依次提供项目操作、帮助和设置，桌面客户端的窗口按钮位于最右侧。点击「设置」可在「界面主题」与「会话设置」之间切换；主题支持经典、明亮、深暗和跟随系统，选择会自动保存。精确时间跳转、自定义速度、时钟偏移和导入诊断位于「会话设置」中，左侧时钟对齐按钮也可直接打开这一页。

设置面板支持方向键切换分类和 Tab 循环导航，关闭后焦点回到入口按钮；在面板中按 Esc 只关闭面板，保留时间轴选区。当前会话显示 Rank 标识，勾选框和移除按钮提供更大的点击区域；没有可显示文件时，计算卡筛选和时间轴视图操作不可用，缩放选区仅在存在选区时可用。通知位于右上方，避免遮挡时间轴。

工作区采用桌面软件式交互：工具栏、列表、标签和表格默认不可拖动选字，关闭非文本区域的浏览器右键菜单、中键自动滚屏、原生文本／图片拖拽，以及 Ctrl／⌘ + 滚轮引起的整页缩放；时间轴内仍按鼠标位置缩放。各面板独立滚动，不将滚动传递到整页。输入框保留文本编辑、选择、剪贴板和右键菜单；事件名称、详情字段、来源文件名及重放信息数值保留选取复制能力，Ctrl／⌘ + A 在这些字段中仅选择当前字段。文件拖入仍可导入，普通文本拖动不会触发文件导入提示。

工作区关闭浏览器拼写检查，搜索框关闭自动补全、自动纠正和首字母大写，避免改写任务名称。

选择上方 **CU 利用率** 视图即可统计。划选时间轴后自动切换到当前选区，也可以手动选择整个时间周期；清除选区后恢复全程统计。时间轴缩放和平移不改变统计范围。

在右侧「选区」面板点击「播放选区」，会从选区起点开始播放，并在选区末尾循环回到起点，沿用当前播放速度。播放栏按钮或空格可以暂停、继续；「关闭循环」可以取消循环，清除选区也会关闭循环。

时间轴上方的全局概览默认显示 **全局任务利用率**，可通过左侧下拉菜单切换为 **全局任务密度**。密度展示事件数量，采用对数刻度；利用率将全程划为最多 180 个时间段，每段以各 CU 任务活动时间并集之和除以「该段时长 × 已记录 CU 数量」，纵轴固定为 0–100%。左侧同时显示全程平均值，悬停柱状图可查看对应时间段的利用率。概览始终统计所有计算卡，独立于卡筛选、选区和视口；时间偏移参与统计，重叠任务不重复计入。切换后保留可视窗口和播放位置，拖动窗口及边缘缩放方式保持不变。

单 CU 利用率 = 该 CU 在统计区间内的任务活动时间并集 / 区间时长。总体利用率 = 各 CU 活动时间并集之和 /（区间时长 × 已记录 CU 数量）；平均活动 CU = 总活动时间 / 区间时长。跨卡使用相同的全局时间范围；来源时钟偏移参与区间裁剪。所有无记录任务的时段（包括某来源记录范围之外）都按无活动计。仅统计记录中出现的 CU，不能推断未采集 CU 的状态，也不等同于硬件 counter 测得的忙碌率。

## 架构与技术

```text
File
  → 解析 Worker：ParserRegistry → PerfettoParser → 官方 Trace Processor WASM
  → ParsedTraceSource：轨道、区间查询、密度、统计、搜索
  → ComputeModelRegistry → MegakernelModel
  → ReplayDataSource：Device / CU / Group 与会话时间
  → PlaybackClock + Pinia
  → Vue 3 工作台 + Canvas 2D 时间轴 / CU 矩阵
```

时间在数据层使用 `bigint` 纳秒。解析和 SQL 在 Worker 中运行；前端只查询可视轨道与活动时间窗口，缩小时显示聚合密度，放大后查询独立区间。播放头覆盖层与轨道背景分开绘制，不把所有事件放进 Vue 响应式状态或 DOM。

时间轴预加载视口前后的时间及上下相邻轨道，按时间覆盖范围复用缓存。连续滚动期间立即绘制已有数据，查询合并到每帧且每批完成后只追赶最新位置，避免查询反复取消和排队；大幅跳转尚未缓存的区域时先显示已有的全局密度，再补充精细数据。缓存按轨道索引，并限制条目数和记录总量。

可视轨道复用预处理后的绘制顺序、相对时间坐标、算子颜色与标签，数据或主题变化时重新生成，离开视口后释放。连续缩放、平移与滚动期间按动画帧调度轨道和覆盖层的同步绘制，避免隔帧更新；视口未变化时跳过重画，操作结束后停止连续调度。大范围时间跳转会重置坐标原点，原始时间戳继续保留为 `bigint`。

框选统计在停止调整约 150 ms 后提交，CU 利用率统计保留 180 ms 延迟；每类统计同时只执行一批查询，并只保留最新的待执行范围。清除选区、切换来源后，旧结果不会覆盖当前界面；已在引擎内执行的查询仍会完成。

CU 矩阵仅重画任务名称、并发数或选中状态发生变化的单元，尺寸和主题变化时完整重绘，并缓存文字测量结果。全局概览缓存柱状图底图，播放、平移和缩放时复用底图，只更新可视窗口与播放头；数据、指标、主题或尺寸变化时重新生成。

`WorkspaceHost` 将宿主文件能力与重放功能隔开；浏览器默认使用文件输入框和下载，桌面启动时才动态加载 Tauri 适配器。后续 VS Code 扩展可以在创建 Vue 应用前通过 `setWorkspaceHost` 注入自己的文件消息桥；当前未实现 VS Code 扩展、Webview 资源 URL / CSP 适配或扩展打包。源文件解析器、计算模式和播放引擎继续共用，不依赖 Tauri API。

使用 Vue 3.5、Pinia 4、Vite 8、Tailwind 4、Reka UI 与 TypeScript 7.0.2。通用 TS 代码由官方原生 TS7 检查；Vue 单文件组件使用 `vue-tsc` 加 `typescript-native-bridge`，其底层同样调用 TS7。桥接包通过 npm 别名占据 `typescript`，官方编译器安装在 `typescript-native`。桥接层有独立版本号，不是把编译器降到 TypeScript 6。`.npmrc` 的 `legacy-peer-deps` 用于桥接预发布版本与 `vue-tsc` peer 范围的兼容；完整依赖由 lockfile 固定。

## 验证与构建

```sh
npm test
npm run typecheck
npm run test:e2e
npm run build
npm run preview
npm run desktop:check
```

浏览器测试优先使用 Windows 已安装的 Edge；其他环境先执行 `npx playwright install chromium`。测试通过手动导入 `trace_demo` 中的开发测试文件，覆盖真实 TP1/TP2 的解析与播放交互、搜索选区、统计、项目恢复、来源隔离、去重和无效文件。设置 `PLAYWRIGHT_BASE_URL` 可以对生产预览地址运行相同测试。

Windows 桌面构建完成后执行 `npm run test:desktop`，直接启动发行程序，通过 WebView2 调试接口和系统对话框自动化验证内嵌引擎、空白启动、用户导入真实 trace 解析、播放、取消、中文路径导入、项目保存与恢复。只在该测试进程启用本机调试端口，结束后关闭测试窗口；截图和临时项目写入忽略目录 `.local/desktop-check/`。

`npm run test:desktop -- --replay-only` 使用应用内的文件输入验证发行程序的空白启动、解析、速度与演示开关、多文件显示、折叠和历史恢复，不执行原生文件对话框的打开／保存流程。桌面测试使用独立的 WebView2 数据目录，避免改动日常使用的历史记录。

开发测试文件的验收数量：TP1 为 76 CU、128,200 个区间；TP2 两来源各 76 CU、222,664 个区间，总计 152 CU、445,328 个区间。

## 当前边界

- 当前是离线重放。样例没有硬件 counter、warp 记录、任务到算子映射或 flow，相关硬件指标显示未采集。CU 利用率视图提供基于任务记录的活动占比，不推测硬件忙碌率、带宽和通信指标。
- 只支持 Perfetto Protobuf 文件。JSON、Hipprof、自定义 `.prof` 等仅预留接口。
- 单文件首版限制 256 MB；每个来源运行一个 WASM 实例，多个大文件会增加内存占用。尚未做 GB 级记录与长时间运行的容量验收。
- 当前按一份来源文件对应一个设备资源解释，支持样例的双 rank 双文件。单文件内包含多张卡时，需要进一步提供明确的设备字段与映射规则。
- 活动窗口上限 250,000 个事件；时间轴精细窗口上限 35,000 个事件，超出时退回密度显示。
- Perfetto v59 会重组同名轨道。解析器利用 descriptor UUID 元数据恢复父链，CU 与事件归属已验证；界面展开的是 Trace Processor 的规范化轨道，不等同于文件内的所有原始 TrackDescriptor。逐一保留原始 descriptor 的检查器仍待补充。
- 实测硬件性能曲线、真实跨卡时钟同步、warp 视图、拷贝通信专用视图与原生大文件后端属于后续工作。当前没有宣称固定帧率或硬件利用率。

详细设计见 `docs/replay-design.md`。
